# انتقال MatchSho به سرور شخصی

سایت و API با HTTPS معتبر پاسخ ۲۰۰ دادند و همهٔ سرویس‌های Compose healthy شدند. پس از تأیید استقلال مقصد، پروژهٔ Supabase Cloud و پروژهٔ قدیمی Vercel در حالت Pause قرار گرفتند؛ چیزی از اطلاعات مبدأ حذف نشد.

- مقصد: `85.198.54.103`، سایت `match-sho.com` و API `api.match-sho.com`.
- PostgreSQL مبدأ و مقصد: 17.6؛ تاریخچهٔ هر ۲۰ migration با baseline تطبیق داده شد.
- دادهٔ نهایی بررسی‌شده: ۲ کاربر، ۱ مدیر، ۲ پروفایل، ۸ رزرو، ۱ پرداخت، ۱ رسید و ۱۳ فایل.
- فایل‌های واقعی Storage از API منتقل و SHA-256 همهٔ فایل‌ها پس از دانلود از مقصد تطبیق داده شد. bucket رسیدها خصوصی باقی ماند؛ مالکیت و metadata نیز تطبیق داده شدند.
- ACL توابع، جدول‌ها، sequenceها و schemaهای برنامه جدا از Cloud استخراج و اعمال شد؛ default grantهای نصب تازه به‌تنهایی معادل مجوزهای Cloud نیستند. بررسی `deploy/verify.sql` پس از اعمال ACL موفق بود.
- نقش سیستمی موجود `supabase_privileged_role` در مقصد حفظ شد؛ grant لاگ مربوط به نقش اختصاصی Cloud که در مقصد وجود نداشت اعمال نشد. بکاپ اصلی تغییر نکرد.
- نقش‌ها و schema با حساب داخلی `supabase_admin` بازیابی شدند. مالک schema و جدول `_matchsho_deploy` برای اجرای استقرارهای بعدی به `postgres` تنظیم شد.
- محیط آزمایش مستقل پس از تأیید متوقف شد؛ داده و بکاپ آن حفظ شده است.

بکاپ نهایی سرور در `/opt/matchsho/shared/backups/cloud-final-20261025-01` است. نسخهٔ دوم خصوصی روی کامپیوتر در `backups/cloud-transfer-20261025-final-01` نگهداری می‌شود. این مسیرها شامل اطلاعات خصوصی هستند و نباید وارد Git یا artifactهای CI شوند.

Cloud با تأیید صریح مالک موقتاً فقط‌خواندنی و jobهای آن غیرفعال شد. تنظیمات قبل از توقف و SQL برگشت در فایل‌های `cloud-maintenance-before.json` و `cloud-maintenance-undo.sql` بکاپ نهایی محفوظ است. بعد از شروع نوشتن در مقصد، اجرای کورکورانهٔ برگشت و فعال کردن دوبارهٔ jobهای Cloud باعث دو منبع داده می‌شود؛ برگشت باید با تطبیق تغییرات جدید انجام شود.

SMTP فعلاً طبق انتخاب مالک تنظیم نشده است؛ ارسال تأیید ایمیل و بازیابی رمز آماده نیست. تنظیمات پیامک، Firebase و زرین‌پال نیز باید با سرویس‌های واقعی تکمیل شوند؛ دادهٔ SQL جایگزین credential سرویس‌ها نیست.

DNS: سه رکورد A برای `@`، `www` و `api` به IP مقصد، TTL برابر ۳۰۰ و فعلاً DNS Only. کلیدهای JWT مقصد جدید هستند و کاربران باید دوباره وارد شوند.
