## دامنه تست

تست‌های SQL شامل اجرای همه migrationها، تطبیق نتایج تاریخی قبل/بعد، جداول دارای RLS، جلوگیری از قیمت دلخواه، پرداخت تکراری و مبلغ متفاوت، انقضای hold، ظرفیت و سطح، تداخل تجهیزات، لغو ناقص و استرداد، CAS درخواست درگاه و ثبت/تأیید نتیجه توسط نقش مجاز است.

سناریوی مالی اضافه: کاربر با پرداخت معلق انصراف می‌دهد؛ intent قبلی نمی‌تواند برای تجهیزات/جایگاه جدید استفاده شود. اگر بانک بعد از اعلام شکست، پرداخت قدیمی را تأیید کند، وجه قدیمی وارد استرداد می‌شود و جایگاه جدیدی که مستقل پرداخت شده، لغو یا مسترد نمی‌شود.

آزمون adapter با transport ساختگیِ مخصوص تست، idempotency key، استعلام پیش از خرید، پاسخ نامعتبر، خطای HTTP، تنظیمات ناقص و verify واقعی‌نما با کد ناموفق را بررسی می‌کند. این پاسخ‌ها هیچ‌گاه در محصول تولید یا انتخاب نمی‌شوند.

مرورگر روی build production و PostgreSQL آزمون در دسکتاپ Chrome و viewport موبایل اجرا می‌شود؛ Auth این محیط مرزی آزمایشی است. مسیر پروفایل → رزرو → تأیید مدیر و نبود پرداخت بدون credential بررسی می‌شود. خطای stream هنگام قطع ناوبری سریع مرورگر ممکن است در log Next دیده شود؛ بررسی‌ها پاسخ صفحات و state نهایی را کنترل می‌کنند.

اندازه‌گیری محلی دو مسیر خانه و رزرو با PerformanceObserver و Navigation Timing در `test-results/**/local-performance.json` ذخیره می‌شود. بدون CPU/network throttling است؛ تخمین INP میدانی یا امتیاز Lighthouse نیست. LCP مشاهده‌شده تا زمان خروج، مجموع layout shift مشاهده‌شده و TTFB برای تشخیص اولیه‌اند. اندازه‌گیری field و تأیید WCAG کامل/ابزار rich-results مستقل انجام نشده است.

## باقی‌مانده برای انتشار واقعی

نتیجه نهایی محلی: ۲۵ تست منطق/SQL/adapter و ۲۲ تست مرورگر موفق؛ lint، typecheck و build موفق. در یک اجرای محلی، LCP مشاهده‌شده صفحه اصلی موبایل ۷۳۲ میلی‌ثانیه و مجموع layout shift مشاهده‌شده صفر بود؛ دسکتاپ ۷۶ میلی‌ثانیه و ۰٫۰۰۲۴. این اعداد تنها نمونه همان اجرای سریع روی localhost هستند و به دستگاه/کش/ناوبری وابسته‌اند؛ برای ادعای CWV مناسب نیستند. اندازه‌گیری مسیر رزرو، ورودی عمومی بدون احراز هویت است؛ فرم کاربر واردشده با E2E عملکردی بررسی شده است.

- بکاپ و restore آزمایشی؛ تطبیق تاریخچه migration و اعمال فقط فایل‌های افزوده.
- پذیرش Auth/SMTP/Storage/RLS روی Supabase staging؛ race چند اتصال PostgreSQL واقعی.
- تنظیم پذیرنده زرین‌پال و تست کامل request → پرداخت → verify → استرداد بانکی.
- قرارداد و اعتبار API باشگاه؛ اجرای bridge روی API مجاز واقعی.
- فعال‌سازی و مانیتور scheduler؛ تطبیق مالی و بررسی سفارش‌های نیازمند توجه.
- پذیرش بصری روی دستگاه‌های واقعی و اندازه‌گیری Core Web Vitals در دامنه انتشار.

فرمت امریکانو و نتایج تاریخی تغییر نکرده؛ تورنمنت حذفی پیشرفته، استرداد بانکی خودکار و ارسال اعلان SMS/ایمیل در این نسخه وجود ندارد. اعلان‌های درون برنامه واقعی و ذخیره‌شده‌اند.
